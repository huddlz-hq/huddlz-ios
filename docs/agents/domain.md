# Domain docs

This repo uses one root `CONTEXT.md` and `docs/adr/`.

## Before exploring

Read `CONTEXT.md` and ADRs in `docs/adr/` that concern the area being changed. If these files do not exist, proceed silently. The domain-modeling skill creates them when terms or decisions are resolved.

## Vocabulary

Use the domain terms defined in `CONTEXT.md` in issues, proposals, and tests. When a needed term is missing, check the existing code and note a real vocabulary gap for domain-modeling.

## Decisions

If a proposal conflicts with an ADR, identify the ADR and explain why its decision should be reconsidered.
